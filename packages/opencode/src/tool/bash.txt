Executes a bash command in a persistent shell session with optional timeout.

All commands run in ${directory} by default. Use `workdir` parameter for different directories. AVOID `cd <dir> && <cmd>` - use `workdir` instead.

IMPORTANT: For file operations (read, write, edit, search), use specialized tools instead.

Guidelines:
- Always quote file paths containing spaces with double quotes
- Optional timeout in ms (default: 120000ms / 2 minutes)
- Write a concise description of the command in 5-10 words
- Output exceeding ${maxLines} lines or ${maxBytes} bytes is truncated to a file. Use Read/Grep to access it. No need for `head`/`tail`.
- Prefer dedicated tools over shell equivalents:
  - Glob (not find/ls), Grep (not grep/rg), Read (not cat/head/tail), Edit (not sed/awk), Write (not echo/cat <<EOF)
- Independent commands: make parallel Bash tool calls. Dependent commands: chain with `&&`. Use `;` if earlier failures don't matter.
- DO NOT use newlines to separate commands

# Git commit workflow

Only commit when requested. Git safety rules:
- NEVER update git config, force push, skip hooks, or amend pushed commits unless explicitly asked
- NEVER commit automatically - only when the user explicitly asks
- Amend ONLY when: user requested it OR pre-commit hook auto-modified files, HEAD was created by you, and commit not pushed
- If commit FAILED/REJECTED by hook: fix and create NEW commit, never amend

Steps: 1) Run git status, diff, log in parallel 2) Draft concise commit message (focus on "why") 3) Stage, commit, verify 4) Fix pre-commit failures with new commit

- Never use interactive git flags (-i). Don't push unless asked. Don't commit secrets.

# Pull requests
Use `gh` CLI for GitHub tasks. Steps: 1) Run git status/diff/log in parallel 2) Draft PR summary from ALL commits 3) Push and create PR with `gh pr create`
- Return PR URL when done. Don't use TodoWrite/Task tools.
